# L2 Runtime Supervisor 退役说明

> 退役日期：2026-08-31  
> 当前架构见 [`双模机制详解.md`](./双模机制详解.md)。

## 结论

L2 Runtime Supervisor 已从运行时代码中彻底移除，不再提供：

- `supervisorPhase`
- `takeover / handoff_pending / cooldown`
- PassiveObserver 与 GoalDriftDetector
- M5–M8 工作区快照、可信度评估、安全检查和反构图
- RecoverySupervisor、RecoveryBoundary、CorrectionBudget、CorrectionPort
- shadow evaluate 和 Supervisor EventTimeline
- checkpoint `supervisorState`

## 替代路径

| 旧能力 | 当前处理 |
|---|---|
| 偏离后 takeover | 向 L1 提交 `recovery_pending`，进入或保持 forced |
| 图级软提示 | 删除；强模型自行纠偏 |
| 图级硬偏离 | ToolGate/GraphExecutor block |
| 严重或重复偏离 | TaskGraph `force_switch` |
| 无可用 fallback | `user_checkpoint`，请求用户介入 |
| 重复工具失败 | Harness 连续失败阶梯与 circuit breaker |
| 恢复预算 | Harness max rounds、token budget、BranchBudget 和 circuit breaker |

## 保留的安全底线

- Permission 与 HostGuard
- ToolGate block 必须跳过执行
- `executionMode` 单写入口
- forced mode lock 与最小驻留
- Verification/Acceptance Gate
- checkpoint、用户中断与 circuit breaker

## 兼容性

这是破坏性升级：

- 旧 `supervisor-config.json` 的 L2 字段会被设置页校验拒绝。
- 旧 checkpoint 的 `supervisorState` 不再恢复。
- Supervisor Timeline API 不再返回 takeover/handoff/graph_hint 事件。
- Web 设置页只展示 L1 Execution Mode 参数。

历史设计与验收文档保留在 `docs/requirement/`，仅供架构演进追溯，不代表当前实现。
