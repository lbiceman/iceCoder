# 多会话并发切换方案

> **状态**：待实现  
> **日期**：2026-08-19  
> **范围**：Web 聊天侧栏 · 移动端会话抽屉 · `switch_session` · **视口只展示激活 session** · `/` `@` `#` 隔离 · 侧栏运行态指示 · 冰豆/ETL/队列/Shell 等同逻辑  
> **关联**：[`多会话-web侧栏-finish.md`](./多会话-web侧栏-finish.md)（已实现列表 CRUD / 单会话切换锁）· [`note-next-commands-finish.md`](./note-next-commands-finish.md)（`/also` `/next` 按会话）· [`聊天页状态保活与断点恢复-finish.md`](./聊天页状态保活与断点恢复-finish.md)（`runningTurn` 快照）

## 1. 目标

用户可以**同时开多个会话**：A 正在跑任务时，左边其它 item 可点、可新建；切到 B 后 A 继续在后台跑。

**视口唯一原则：聊天主区只展示当前激活 session 的内容。** 冰豆、执行透明层、任务队列、Shell 坞、确认框、流式气泡等凡是「一块单例 UI」的，都按同一套逻辑：后台会话只更新自己的袋，不往画布上画。切到谁，才把谁的袋刷上去。

侧栏每个会话右上角用圆点表示运行态（**聊天主区内**，这是唯一允许展示非激活会话运行态的控件；进程级 MCP/连接/系统通知见 §4.4 例外）：

| 状态 | 形态 | 语义 |
|------|------|------|
| 进行中 | 呼吸圆点 | 该会话 harness / 队列仍在跑 |
| 已完成 | 静止绿色圆点 | 最近一次任务正常结束（`model_done`） |
| 失败 | 静止红色圆点 | 最近一次任务异常结束 |
| 空闲 | 无圆点 | 从未跑过、用户主动 Stop、或用户已点进该会话看过结果 |

**默认组合**：一切走不杀后台、侧栏不锁点击、命令打在当前视口会话。不做双聊天窗。

---

## 2. 非目标

- 同一屏两个完整聊天窗 / 两个输入框
- 多条 WebSocket 连接（一条 WS + 单订阅前台会话即可）
- 第一期不做「后台 confirm 弹到当前视口」；confirm 无订阅者时暂停计时，侧栏保持呼吸（见 §7.4）
- 第一期不做同工作区写锁 / 跨会话 MCP 隔离
- 不改 CLI REPL 的单会话模型
- 不把进程级 `activeSessionId` 做成服务类或 DI
- 不给每个会话各克隆一套聊天 DOM / 冰豆 / ETL 面板（全部单例 DOM + 每会话一袋）

## 3. 现状（为何只能一个会话）

后端执行核**已经按 session 分片**，跨会话并行是铺好的：

- `sessionProcessing: Set<string>`：防的是**同一会话**被两个连接各跑一个 harness，不是全进程一把锁
- `runSessionMessageLoop` / `{sessionId}.task-queue.json` / `pendingAlsoNotesBySession` / `fileBrowserStateBySession` / `runningTurns` / `structuredCache` / `broadcastToSession`

真正锁死的是产品策略 + 视口单例：

| 层 | 行为 | 文件 |
|----|------|------|
| 前端锁 | `isWorkloadActive()` 为真 → 侧栏 `is-switch-locked`，非当前 item `pointer-events: none`；新建按钮 `is-disabled` | `chat-session-sidebar.js`、`mobile-session-drawer.js`、`chat.css` |
| 后端杀 | `switch_session` 对 leaving 会话 `abortSession` + `stopForegroundShellWorkForSession` | `chat-ws-inbound.ts` |
| 全局 id | 进程级 `activeSessionId`；入站大量 `getSubscribedSessionId(ws) \|\| getActiveSessionId()` | `chat-ws-runtime.ts` |
| 单订阅 | 一条 WS 只订一个 session，切走后收不到后台 stream | `chat-ws-broadcast.ts` |
| 视口单例 | `wsProcessing` 一个 boolean；`onSessionSwitched` 会 `FileRef.clearInput()`，`#` 芯片甚至不清 | `chat-websocket.js`、`chat-page.js` |

现存 `.chat-sidebar-item-dot` **只出现在当前选中项**，用 accent 色呼吸表示「我被选中」。本方案把它改成**运行态指示**，选中只靠 `.active` 卡片高亮。

旧文档 [`多会话-web侧栏-finish.md`](./多会话-web侧栏-finish.md) §0.6 写过 `session_switched.reason === 'processing'` 拒绝切换；当前代码已改为「切走即 abort」，两套行为都要废掉，改为「切走不杀」。

## 4. 架构：前台视口 + 后台继续

```text
                    ┌─ session A：Harness 继续跑，runningTurns 更新
  用户点 B ──► WS switch_session 只换本连接订阅
                    │
                    ├─ 不再 abort A，不再停 A 的 copilot PTY
                    ├─ 进程 activeSessionId 仅作「最近聚焦」（冷启动 / 扫码）
                    └─ 视口换成 B：历史 + 草稿袋 + 工作区 + 发送钮跟 B 的 busy

  侧栏圆点 ◄── session_run_state 广播给「所有 chat 客户端」
               （不能只 broadcastToSession，否则看 B 时收不到 A 结束）
```

### 4.1 后端原则

1. `switch_session`：**只** flush leaving 会话缓存、换 `subscribeWsToSession(ws, targetId)`、回 `session_switched` + 目标会话 `runningTurn` / workspace / bgTasks。  
   **禁止** `abortSession(leaving)`、**禁止** `stopForegroundShellWorkForSession(leaving)`（今天切走会杀掉 leaving 的 bound 前台 shell；copilot PTY 本来就不杀）。  
   幂等判断必须是 `targetId === getSubscribedSessionId(ws)`，**禁止**跟进程级 `getActiveSessionId()` 比（多连接时全局 id 已是别人的会话，会误 flush / 误切）。
2. 入站 `message` / `stop` / `confirm_reply` / `bg_task_stop` / `/also` `/next` `/shell` `/open` 一律以 `getSubscribedSessionId(ws)` 为准，禁止 `|| getActiveSessionId()` 作为业务 sid（今天 `bg_task_stop` 仍走全局 id）。
3. `setActiveSessionId` + `persistLastActiveSessionId` 仅表示最近聚焦，给冷启动 / QR 默认会话用。`runSessionMessageLoop` 里不要每轮写 last-active。
4. `resetSupervisorRuntimeCache()` 不要绑在每次 `switch_session` 上。

### 4.2 前端原则

1. 去掉 `isSwitchLocked` 对 item / 新建的禁用；忙态只驱动**当前视口**发送钮（有内容=发送入队，空=Stop）。
2. `ChatWebSocket` 的 processing 改为按 session：`processingBySession[sid]`；`isProcessing()` 默认返回当前 active session。
3. **任务向 WS 包必须带 `sessionId`**，再走 §4.4 闸门。今天 `stream` / `status` / `step` / `error` / `confirm` / `tokenUsage` 多数**没有** sid，闸门形同虚设，A 的在途包会写进刚切过去的 B。
4. 切换时换视口，不重连 WS。单订阅意味着后台会话的 stream **不会**再到达本连接（见 §4.4 袋的来源）。切回靠 `runningTurn` + REST，不靠后台实时袋。
5. Composer **草稿袋**按 `sessionId` 存：textarea、`#` 技能芯片、`@` 文件引用、待发图片。打开中的 `/` `#` `@` 面板、未关的 `~scan` 二维码在切走时关闭。

### 4.3 已可复用、不必重做

`sessionProcessing`、`enqueueAndMaybeKickoff`、`TaskQueueManager`、`pending-note`、`fileBrowserStateBySession`、`shellCollabActiveBySession`、`structuredCache`、`runningTurns`、`sessionAbortControllers`、工作区 `{id}.workspace.json`。ETL 的 `ChatExecutionFlowStore`、任务队列卡片、Shell dock 的 session cache 已有按 sid 存的雏形，缺的是「非激活禁止 paint」。

### 4.4 视口唯一原则：仅展示激活 session

冰豆、ETL、队列、确认框都是同一条规则。聊天页里凡是单例控件，一律：

```text
收到事件
  → 无 sessionId 且属于任务向（stream/step/status/…）视为协议缺陷，必须先补 sid
  → event.sessionId !== activeSessionId
      → 不碰视口 DOM（不弹 Modal、不改冰豆、不改输入框、不 append 消息）
      → 全员类事件（session_run_state）只更新侧栏圆点 Store
      → 其余任务向事件在单订阅下本就不该到达；若到达（切订阅在途包）则丢弃或只写入该 sid 的袋
  → event.sessionId === activeSessionId
      → 更新袋 + 画视口

switch_session 到 sid
  → capture 当前视口进 outgoing 袋
  → 用 incoming 的 runningTurn / REST / 草稿袋 重绘同一套 DOM
```

**单订阅下袋从哪来（避免实现时误以为后台会持续推 step）：**

| 来源 | 说明 |
|------|------|
| 切走时 capture | 输入框、芯片、冰豆闭包、ETL 面板、队列编辑态 |
| 切回时 `runningTurn` + 拉历史 / plan / queue / bgTasks | **进行中会话的权威状态**；袋可能略旧，以服务端快照为准 |
| `session_run_state` 全员广播 | 只更新侧栏圆点，不画主区 |
| 切订阅瞬间的在途包 | 闸门防串；这是闸门的主用途，不是后台直播 |

因此：看 B 时 A 的冰豆袋**不会**跟着 A 的每一步刷新。切回 A 必须 `restoreFromRunningTurn`，不能只 restore 切走那一刻的袋。

**必须补 `sessionId` 的任务向 WS 类型（当前多数缺失）：**

`status` · `stream` · `reasoning_stream` · `stream_end` · `response` · `step` · `error` · `info` · `pulse` · `tokenUsage` · `confirm` / `confirm_resolved` / `confirm_timeout` · `tool_output` · `memory_notice` · `harness_state`

已有 sid、守住闸门即可：`user_message_appended` · `also_*` · `task_queue_updated` · `session_updated` · `workspace_updated`。

**必须跟激活会话走的视口内容：**

| 区域 | 现状风险 | 切到空闲 B 时 |
|------|----------|----------------|
| 消息列表 / 流式气泡 / 思考流 / live 工具条 | `isStreaming` 全局；`stream` 无 sid | 换成 B 的历史；无流式 |
| 欢迎空态 | 看消息数 + 全局 busy | 只看 B 是否空闲且无消息 |
| 输入框 + `#` `@` 芯片 + 附件 + slash 面板 | 单例 composer | 换成 B 的草稿袋；关面板 |
| 发送 / Stop 钮 | `isWorkloadActive()` 看全局 | 只看 B 是否 busy |
| 冰豆表情 / 气泡 / 轮次 / token 环 | `ChatPetBridge` 单例 | 换成 B；空闲则 idle |
| 桌面悬浮冰豆 | 镜像页面冰豆 | 跟随选中会话 |
| 执行透明层面板 + 快照时间线 | 桥已按 sid 存流，`step` 无 sid 仍会串 | 换成 B 的 plan；无则收起/空 |
| `/next` 任务队列卡片 | `setItems` 已有 sid 过滤 | 换成 B 的队列 |
| Shell 协作指示 + PTY 坞 + 后台任务芯片 | 切走会 `rebindBgTaskPusher` 到新 sid，A 的 live 更新停；切回再 hydrate | 换成 B 的任务；B 无则隐藏 |
| 工具 / Shell 强制确认弹窗 | `activeConfirmId` 全局一份 | A 的 confirm **不得**弹在 B 上；点回 A 再弹 |
| 楼梯导航 / 工作区脚注 | 绑当前消息区 / 当前 workspace | 换成 B |
| `~scan` 二维码 | 绑定打开瞬间的 sid | **切会话时关掉弹窗**，避免 A 的码留在 B |
| 移动端工作页 / 抽屉 | `isSwitchLocked` + `isWorkloadActive` | 与桌面同一闸门；`mobile-work-page.js` 的 busy 只看激活会话 |

**允许展示非激活会话的（例外，不要误伤）：**

| 区域 | 为什么 |
|------|--------|
| 侧栏 / 抽屉列表 + 右上角运行态圆点 | 切换器；用户要看见谁在跑 |
| 连接状态、MCP ready、Tunnel、监管模式按钮 | 进程级，不是某次对话 |
| 设置 / 记忆 / 技能库页面 | 不是聊天视口 |
| 桌面系统「任务完成」通知（窗口不在前台时） | 用户没在看视口；A 后台跑完仍应提醒。点击通知应 `switch_session` 到该 sid |

漏网检查：新增任何聊天页 UI 时，先问「它有没有 `sessionId`」。有 → 必须过闸门。没有且会随任务变 → 补 `sessionId` 再过闸门。

**切会话刷盘顺序（`onSessionSwitched`，§7.1 与此相同，不另写一套）：**

1. 关 slash / skill / file 面板、关 QR 弹窗；当前 confirm **不 resolve**，挂回 outgoing 袋
2. capture：composer 草稿、冰豆袋、ETL（`flushOutgoingSession`）、队列编辑态
3. `Session.setSessionId` → 拉 B 历史 / `runningTurn` / plan / queue / bgTasks / shell dock
4. restore：草稿、冰豆（**进行中以 `runningTurn` 为准**）、ETL、队列、dock、token、发送钮
5. 若 B 的 `runPhase` 为 done/error，按 §6.3 清侧栏圆点（running 不清）

禁止「只清不存」（今天 `FileRef.clearInput()` 就是这种）。

## 5. `/` `@` `#` 隔离

命令打在**当前正在看的会话**上。在 B 里敲 `/also` 绝不能注入后台 A。

| 输入 | 隔离 |
|------|------|
| `/also` | `queueAlsoNote(当前 sid)`；当前 sid 无 running turn 则拒绝 |
| `/next` 与默认发送 | 入当前 `{sid}.task-queue.json` |
| `/shell` | 只改当前会话 collab / PTY；A 的 PTY 切走后继续活（copilot 生命周期不变） |
| `/open` | 当前会话 `fileBrowserState` + 当前 `workspaceRoot` |
| `#技能` | 草稿袋 `selectedSkills[]`；发送进当前消息 `skills` |
| `@文件` | 草稿袋 `fileRefs[]`；发送进当前消息 `referencePaths`；浏览根 = 当前 workspace |
| Stop | 只 `abortSession(当前订阅 sid)` |

同一条消息里 `/shell` + `@` + `#` 仍走现有 `buildUserMessageDisplayFields`，跟 `runSid` 走即可。

**验收反例：**

- A 运行中切到 B，B 输入框残留 A 的 `#登录.md` 和 `@src/foo.ts` → 不合格
- A 运行中在 B 发送 `/also 补充` 却进了 A → 不合格
- 切回 A 后草稿（未发送的 `/next` 半成品、芯片）丢失且不可恢复 → 不合格

## 6. 侧栏运行态圆点

### 6.1 位置与结构

每个 `.chat-sidebar-item` 已经是 `position: relative`。在卡片**右上角**放独立指示器（不要再占用 title 行里「选中呼吸点」的位置）：

```html
<div class="chat-sidebar-item" data-id="…" data-run-phase="running|done|error">
  <span class="chat-sidebar-item-run-dot" aria-hidden="true"></span>
  <!-- 原有 body / title / meta -->
</div>
```

- `top: 8px; right: 8px`；直径 8px，与现有 `.chat-sidebar-item-dot` 同尺寸
- **废弃**「仅 active 项渲染 `.chat-sidebar-item-dot`」；选中只靠 `.chat-sidebar-item.active` 背景
- 删除按钮仍 hover 才出现。有圆点时 title 行右侧留出约 16px，避免字与点重叠；hover 出 × 时圆点可略降透明度，但进行中呼吸点不得消失
- 移动端 `.mobile-drawer-item` 同样右上角一枚点，并取消 `item.disabled = locked`

### 6.2 三态视觉

复用 token：`--accent`（进行中）、`--success`（完成）、`--danger`（失败）。暗色已有 `#55c58e` / `#df8290`。

| `data-run-phase` | class | 视觉 |
|------------------|-------|------|
| `running` | `.is-running` | 填充 `--accent`，`box-shadow` 用 `--accent-glow`，**呼吸动画** |
| `done` | `.is-done` | 填充 `--success`，无动画，可带极淡 success glow |
| `error` | `.is-error` | 填充 `--danger`，无动画 |
| （无） | 不渲染节点 | 空闲 |

进行中呼吸**复用**现有 `@keyframes chat-sidebar-dot-breathe`（5s ease-in-out，scale 0.8↔1.2）。周期可收到 ~2s，让后台任务更醒目；`prefers-reduced-motion: reduce` 时停动画，进行中改为静止 accent 点。

`aria-label` 建议：`任务进行中` / `任务已完成` / `任务失败`。

### 6.3 状态机

```text
  (无点)
     │  kickoff / status=processing / 有 runningTurn
     ▼
  running（呼吸）
     │
     ├─ stopReason === model_done 且队列已空  →  done（绿点）
     ├─ 失败类 stopReason 或 WS type=error     →  error（红点）
     ├─ user_abort（用户 Stop）                →  无点
     ├─ user_checkpoint（监管暂停）            →  保持 running
     └─ model_done 但队列还有下一项            →  保持 running
```

**失败类**（红点）：`error` · `timeout` · `circuit_breaker` · `verification_exhausted` · `max_output_tokens` · `max_rounds` · `token_budget` · `stop_hook` · loop 里 `catch` 推的 `type: 'error'`。

**不算完成也不算失败：**

- `user_abort` → 清点（用户自己停）
- `user_checkpoint` → 保持 `running` 呼吸（监管暂停、等人；不是失败）。点进该会话后走现有 checkpoint UI，圆点仍呼吸直到用户处理完或 Stop

**绿/红点何时消失：**

1. 用户**点进**该会话且 phase 为 done/error（视口切过去表示已看见结果）。点进 **running** 不清点
2. 该会话再次进入 `running`（新一轮覆盖绿/红）
3. 会话被删除

不做定时自动消失（用户可能去了别的应用）。F5 / 重连：进程内 `runPhaseBySession` 仍在则 `connected` 包带上全量 `sessionRunStates[]`；进程重启后终端绿/红不持久化（进行中仍可由 `getProcessingSessionIds()` 恢复呼吸）。

### 6.4 协议：必须广播给所有聊天客户端

现有 `status: processing | idle` 只 `broadcastToSession`。看 B 时 A 结束，侧栏收不到。

新增（或扩展 `session_updated`）：

```ts
// 发给全部 chatClients，不只当前订阅者
{
  type: 'session_run_state',
  sessionId: string,
  phase: 'running' | 'done' | 'error' | 'idle',
  stopReason?: StopReason, // done/error 时带上，idle(user_abort) 可带 user_abort
}
```

触发点（`chat-ws-loop.ts` 已有骨架，补 phase + 全员广播即可）：

| 时机 | phase |
|------|--------|
| `runSessionMessageLoop` 进入、`ensureRunningTurn` 之后 | `running` |
| 本轮 `model_done` 且马上 dequeue 下一项 | 保持 `running`，不发 done |
| loop 正常结束且最后 `stopReason === 'model_done'` | `done` |
| 失败类 stopReason，或 `catch` 已发 `type:error` 之后 | `error` |
| `user_abort` / `abortSession` 导致 loop 退出 | `idle` |
| `connected` | 附带当前所有非 idle 的 `{ sessionId, phase }[]`（含 running；done/error 若仍在内存） |

前端：`ChatSessionStore` 持 `runPhaseBySession`；`session_run_state` 更新后 `emit()` → 侧栏 `renderList()`。不要等整表 `GET /api/sessions`。

`chat-websocket.js` 解析该事件时**不得**用它去改全局 `wsProcessing`；视口 busy 仍只看当前 `sessionId` 的 `status` / stream。

### 6.5 与旧呼吸点、Shell 徽章的关系

- Shell 协作徽章留在 meta 行，与右上角运行点无关
- 当前选中 + 进行中：卡片 `.active` **同时**右上角呼吸
- 当前选中 + 刚完成：绿点在点进的那一刻按 §6.3 清掉，因此前台会话通常看不到自己的绿/红点（正在看结果）。后台会话才需要绿/红提醒

## 7. 切换与视口细节

### 7.1 `onSessionSwitched`

与 §4.4 刷盘顺序相同，不在此重复。补充两点：

- 禁止无条件 `FileRef.clearInput()` 而不存袋
- `syncComposerActionState()` 只根据 **incoming** 是否 busy；不要再 `syncSwitchLockState`

### 7.2 Stop / 发送

- Stop：只停当前订阅会话
- 发送 / `/next`：入当前会话队列；当前空闲则 kickoff，忙碌则排队（现有语义不变，只是锁从「全站一把」变成「每会话一把」）
- A 在跑时，B 可以立刻发任务 → B 自己 kickoff，与 A 并行

### 7.3 新建 / 删除

- 忙碌时允许新建并切过去
- 删正在跑的会话：先 `abortSession` + 现有 purge / tombstone，再从列表移除（与今天删会话清理钩子对齐）
- 删非当前会话：不打断当前视口

### 7.4 Confirm（服从 §4.4）

A 的危险操作确认**不得**盖在 B 的视口上。切走后：该 session 无订阅者则暂停超时；有订阅但不在前台则只更新袋。点回 A 再弹出。侧栏 A 保持呼吸。

### 7.5 PC + 扫码

两条 WS 本来就能订不同 session。拿掉「切换即改全局并 abort」之后，两端才能各聊各的。QR 对齐只改**那条**连接的订阅，不要 abort 另一端正在跑的会话。

### 7.6 冰豆（§4.4 的实例）

`ChatPetBridge` / `SessionPet` 是单例，服从 §4.4。切回进行中的 A **以 `runningTurn.petState` 为准**，不要以为切走期间袋会跟着 A 的 step 更新。MCP / Tunnel / 监管模式是进程级通知，可以打在当前冰豆上。

## 10. 分期

**P0 / P1 必须同一批上线。** P0 只是内部切片（去锁、不杀、圆点、补 sid），单独发布会串台。

**P0 — 接线（不单独发布）**

- 去侧栏 / 抽屉锁
- `switch_session` 不 abort、幂等看订阅 id
- 任务向 WS 包补 `sessionId`
- `session_run_state` 全员广播 + 右上角三态点
- Stop / 发送跟当前视口

**P1 — 视口闸门（与 P0 同发）**

- §4.4 闸门 + 草稿袋 + 切回以 `runningTurn` 刷冰豆/ETL/队列/Shell
- confirm 无订阅者暂停超时；不弹在非激活视口
- 入站全部 subscribed sid；切走关 QR

**P2 — 可感知后台**

- 并发上限 3
- 同仓库警告
- （可选）侧栏 `need_confirm` 角标；点击通知跳到对应 session

## 11. 测试要点

- A `processing` 时点 B：A 的 `sessionAbortControllers` 仍在，B `session_switched.ok === true`
- A 在跑时侧栏 B 可点、新建可点；A item 右上角 `is-running` 呼吸
- A `model_done` 且队列空：A item 变 `is-done` 绿点；点进 A 后绿点消失
- A `catch` / `stopReason=error`：A item `is-error` 红点
- A 用户 Stop：A item 无点
- A `model_done` 后队列还有 `/next`：保持呼吸，不闪绿
- 看 B 时 A 结束：B 的连接也能收到 `session_run_state`（全员广播）
- 切到 B 再切回 A：若 A 仍在跑，`runningTurn` 能还原流式/工具条和冰豆
- **A 在跑时切到空闲 B：消息区、冰豆、ETL、队列、Shell 坞、confirm、流式气泡全部是 B 的；侧栏 A 仍呼吸**
- 停在 B 时 A `model_done`：视口不闪 A 的「已完成」；系统通知（窗口失焦）仍可发
- B 的 `#` `@` `/also` 不进入 A 的 structured / pending-note
- 切走 A 时 A 若在等 confirm：不得在无人订阅时自动拒绝；点回 A 仍能确认
- A `user_checkpoint`：侧栏保持呼吸，不是红点
- 无 `sessionId` 的 `stream`/`status` 不得把 B 的视口打成 processing
- 点进 running 的 A：圆点仍呼吸；点进 done 的 A：绿点消失

## 12. 决策摘要

| 决策 | 选择 | 理由 |
|------|------|------|
| 交互模型 | 单视口 + 后台继续 | 复用 runningTurn / broadcast，不重做 chat-page |
| 切走 | 不杀任务 | 否则无法多开 |
| 圆点广播 | 全部 chatClients | 否则前台订 B 时看不见 A 结束 |
| 绿/红消失 | 点进该会话或再开跑 | 避免错过结果，也不永久钉死 |
| `user_abort` | 无点 | 主动停 ≠ 失败 |
| 旧 active 呼吸点 | 废弃 | 呼吸专用于进行中，避免和选中抢语义 |
| 视口 | 只画激活 session | 单例 DOM + 每会话一袋；事件 sid ≠ 激活则不 paint |
| 侧栏圆点 | 可展示非激活 | 切换器需要看见谁在跑 |
| 草稿袋 + 闸门 | 与去锁同发 | 单独去锁会串 `#` `@` / 流式 / 冰豆 |
| 切回进行中会话 | 以 `runningTurn` 为准 | 单订阅下袋不会后台直播 |
| 任务向 WS | 必须带 `sessionId` | 否则闸门无法工作 |
| 冰豆 / ETL / 队列 / Shell / confirm | 与视口同一闸门 | 禁止各做一套例外逻辑 |
