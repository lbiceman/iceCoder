# 执行流 · 最终效果

> 只描述做完之后用户看见什么、怎么用。不涉及实现、接口、改哪些文件。
>
> 执行流是工作台上的**只读回显**：展示这个 session 里 Harness 做过的工作。不打开文件、不回滚、不发送指令。

---

## 1. 一句话

打开一个会话的「执行流」，看到的是这本会话的**工作编年史**：用户每说一句、Harness 就记下一章；章里是模型一轮轮做了什么。聊天区仍是对话和工具原文；检查点仍是可回滚的位置。

---

## 2. 它是什么 / 不是什么

**是**

- 整个 session 的执行历史，不是「当前这一问」的临时看板。
- 发下一条消息后，上一章还在，新工作接着往下记。
- 刷新、晚开面板、从另一端进来：只要会话还在，编年史还在。
- 展示可以换说法、换折叠方式，但内容都来自该会话的检查点回显。

**不是**

- 不是聊天记录的缩略版（不展示模型正文、思考、命令输出全文）。
- 不是文件浏览器、不是 diff、不能点文件打开。
- 不是检查点操作台：没有恢复、没有删除检查点。
- 运行中不能从这里打断、改提示、跳过步骤。

---

## 3. 和旁边两块怎么分工

| 区域 | 用户来这里是为了 |
|------|------------------|
| 聊天 | 看说了什么、工具原文、完整输出 |
| **执行流** | 扫「这个会话工作是怎么推进的」 |
| 检查点 | 回到某一问之前的状态；看本会话改过哪些文件 |

同一根时间轴：用户的每一句话对应执行流的一章、也对应检查点上的一个点。左边聊天是对话，右边执行流是工作，检查点是可以倒带的刻度。

---

## 4. 打开面板时默认长什么样

工作台标题、监管条（若有）、Tab（执行流 / 检查点）、底栏（上下文 / 工具累计 / 会话耗时）都还在。

**执行流默认是「章节目录」，不是一长串工具。**

每一行是一次用户意图（一次 Harness 完整工作），从上往下按时间排，**最新一章在最下面**，进入时滚到最新。

```
iceCoder 工作台                                    —
────────────────────────────────────────────────────
⚠ 已进入监管模式（多文件写入 · 第 2 章）     查看详情
────────────────────────────────────────────────────
  执行流                              检查点
────────────────────────────────────────────────────

  ①  补测试并跑 vitest
      完成 · 6 轮 · 改 3 个文件 · 12s

  ②  登录失败时不要清掉表单
      完成 · 11 轮 · 改 8 个文件 · 监管曾介入 · 1m 02s

  ③  把空态文案改短一点                         ← 当前
      进行中 · 第 4 / — 轮 · 已写 2 个文件
      正在修改 src/public/js/chat-ui.js · 3.1s

────────────────────────────────────────────────────
上下文 31,262/1000K (3.1%)    工具 20    时间 00:29
```

折叠的一章，一眼能读到：

- 用户那句话的短摘要（不是技能标签墙、不是整段 prompt）
- 状态：进行中 / 完成 / 失败 / 已暂停 / 用户停止
- 这章里 Harness 跑了多少轮
- 这章改了几个文件（没有改动就不写）
- 这章是否进过监管、是否压缩过、是否熔断——有才出现
- 这章耗时

**没有任务图的问答章同样占一行**，不会整栏空白。没有工具的收尾不会单独占满一屏。

当前章（最后一行）默认展开；更早的章默认收起。

---

## 5. 点开一章之后

展开后，这一章变成「这一次 Harness 工作」的内部时间轴。单位是 **Harness 的一轮**（一次模型调用 + 它带出的工具），不是聊天气泡。

```
  ②  登录失败时不要清掉表单                    ▾
      完成 · 11 轮 · 改 8 个文件 · 1m 02s
      ────────────────────────────────────────
      目标  修登录失败清空表单
      阶段  实施修改 → 验证结果
      监管  多文件写入 · 第 2 轮进入
      ────────────────────────────────────────
      1  读取登录与表单相关实现          完成  4.2s
         读了 3 个文件
      2  修改提交失败时的状态处理        完成  9.8s  ▾
         做了什么
           ✓ 修改 src/.../LoginForm.tsx     1.2s
           ✓ 修改 src/.../session.ts        0.8s
         为什么这么做
           为落实「失败时保留表单」；监管：多文件写入
      3  运行相关测试                    失败  6.1s
         ✓ 执行 vitest LoginForm            6.1s  ← 未通过
      4  按测试失败调整断言              完成  5.0s
      …  （其余轮次可继续展开）
      ✓  整理结论                        完成  2.4s
         模型判断本章目标已达成
```

规则：

- 先看到轮次标题（收集上下文 / 修改文件 / 跑测试 / 整理结论），不是 `read_file` 这种工具名。
- 再展开一轮，才看到这一轮的工具清单：意图一句 + 路径或命令短预览 + 耗时 + 成败。
- **没有 stdout、没有 diff、没有思考正文。** 要原文，去聊天区对应位置（若能跳转：点工具行滚到那条 trace；跳不到也不在这里复制一份）。
- 「整理结论」是该章最后一轮的收尾，挂在章里面，不是面板里唯一的一张卡。
- 任务图若有：在章头用「目标 / 阶段 / 进度」显示；没有任务图时章头只留用户摘要和统计。

同一章里的监管、压缩、熔断，作为这一章的标记，不每轮都刷一条永久黄条。会话级监管条仍可留在面板最顶上（当前是否处于监管），和章内标记不打架。

---

## 6. 正在跑的时候

最新一章是活的：

- 章标题旁是「进行中」，轮次在往下长。
- 章头有一条「正在做」：当前工具 + 文件或命令 + 已耗时。用户不用翻聊天也能知道这一秒在干什么。
- 当前轮次自动展开；刚结束的轮次收成一行。
- 底栏数字随这次会话累计更新（上下文是此刻窗口；工具数、时间是本会话工作量）。

上一章全部冻结：不再闪、不再改统计，除非用户去检查点倒带（倒带后编年史截到那个点，那之后的章消失——因为那些工作已经被回滚掉）。

发下一条用户消息：

- 上一章打上完成或停止，收起。
- 底下出现新的第 N+1 章，进入进行中。
- **上面的历史章节都还在。**

---

## 7. 和检查点 Tab 对上之后

两个 Tab 是同一根「用户消息」轴， sens 不同。

**执行流**

- 每一章都能展开看 Harness 怎么干的。
- 没有任何「恢复」「打开文件」按钮。

**检查点**

- 每个点对应同一句用户消息。
- 仍是：时间轴 + 本会话变更文件；点文件用系统程序打开；点检查点可以恢复。

用户在执行流里看「第二章改了 8 个文件、测试先失败再修好」；要回到第二章之前，切到检查点 Tab 选那个点。不要求执行流里嵌一套恢复 UI。

点检查点时间轴上的某一档，如果仍停在执行流 Tab：目录滚动到对应那一章并展开（只读预览「当时那章的工作」）。恢复动作只发生在检查点 Tab。

---

## 8. 刷新、晚开、空会话

- **空会话 / 还没发过话**：执行流是一句「等待模型开始执行」，没有假卡片。
- **只说过话、Harness 还没转起来**：已有一章「进行中」，轮次区仍可为空，章头已有用户摘要。
- **刷新或晚开面板**：不应再出现「轮次 1–1 未载入、去聊天区展开」。目录和已结束章应直接齐；正在跑的章接到当前进度。
- **只有收尾、中间工具都在聊天折叠里**：最终效果里不允许这样。那 20 次工具应落在对应章的对应轮次下；页脚「工具 20」和目录能对上。
- **超长会话**：默认仍只展开当前章；更早的章保持一行。可以「加载更早的章节」，但不把几百轮工具一次性摊开。

---

## 9. 几种工作在编年史里长什么样

**短问答（没有任务图、几乎没工具）**

```
  ①  这段报错是什么意思
      完成 · 1 轮 · 3.2s
```

展开后可能只有一轮「整理结论」。合法，因为这一章本来就没有施工。

**一次中等实现（对应你现在那张偏空的截图，做完之后应长这样）**

目录上能看到当前章不只是「整理结论」一张卡，而是例如：

```
  ①  （上一问的摘要）…     完成 · …
  ②  （本问的摘要）…       完成 · 2 轮 · 工具 20 · 00:29
```

展开第 ② 章：第 1 轮是实际工具（读/改/搜/命令），第 2 轮才是整理结论。监管「多文件写入」写在第 ② 章头或第 1 轮的「为什么」里。页脚 20 次工具与第 ② 章对得上。

**长任务、多问接力（「再改一下」「测试还是红」）**

三章、四章排在一起。用户能看出：第一问搭好、第二问返工、第三问收尾。不会每问一次侧栏被洗成空白。

**失败 / 熔断 / 用户停止**

该章徽章是「失败」或「已停止」，展开能看到最后一轮哪次工具红了，或「用户停止 / 熔断保护」。不把错误栈打在侧栏。

**压缩**

章上有小标记「本章发生过压缩」。不在执行流里展示压缩后的摘要正文。

**子代理**

章内一行状态即可：「分析中」或「分析已就绪」。点它若跳转，也是去聊天区那条摘要，不在执行流里嵌分析全文。

## 10. 用户怎么用（走查）

1. 打开旧会话，不说话：执行流已是多章目录，能回忆「上次改到哪」。
2. 继续打一句：新章出现在最下，旧章还在。
3. 离开去倒水：回来看「正在做」那一行，不必翻聊天折叠。
4. 觉得改多了：切检查点，回到某一章之前；再切回执行流，后面的章没了，符合回滚后的世界。
5. 想看某次 `vitest` 的完整输出：在执行流里点到那一轮的工具，跳到聊天区那条；侧栏自己不显示输出。
6. 移动端：仍是底部 sheet，只有执行流。目录同样是章；展开当前章。检查点保持桌面 Tab，不塞进执行流。

---

## 11. 底栏在最终效果里表示什么

- **上下文**：此刻窗口占用（活的）。
- **工具**：本会话编年史里累计的工具次数（与各章合计一致）。
- **时间**：本会话处于「有工作在跑或已跑过」的累计墙钟，不是单章秒表。章自己的耗时写在章行上。

三者都是读数，不是按钮。

---

## 12. 最终效果的验收直觉

不必看代码，用眼睛就能判断有没有做成：

1. 连说两句用户话，侧栏是两章，不是第二句把第一句擦掉。
2. 一章折叠时像目录，展开才像施工记录。
3. 再也不会出现「页脚工具 20、中间只有整理结论、黄条叫人去聊天区翻历史」。
4. 执行流里找不到「打开文件」「恢复检查点」。
5. 空会话干净；长会话能往回翻章，而不是一屏几百条工具。

满足这五条，就是这份效果文档所说的终态。
