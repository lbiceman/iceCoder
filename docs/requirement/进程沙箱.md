# 进程沙箱（简化版）：工作区外写入确认

> **状态**：已实现
> **版本**：v1.1（替换 v0.3 的系统级方案）
> **日期**：2026-10-30

锁定工作区后，Agent 的命令如果要写或删工作区外的路径，先让用户确认。

不改进程权限，不改目录 ACL，不加原生代码。只在执行前看一遍命令文本，判断它会写到哪里。

---

## 1. 范围

**挡什么：** 命令里直接写出来的越界写入。例如 `rm -rf ../other`、`cd .. && rmdir /s /q x`、`del C:\Users\me\Desktop\a.txt`、`echo x > %USERPROFILE%\a.txt`、`npm i -g xxx`。

**不挡什么：** 程序运行起来之后自己决定往哪写。例如 `node build.js` 里的 `fs.writeFileSync('C:/x')`、`python -c "open(...)"`、`npm install` 写全局缓存。

目标是防误删、误改。模型误操作时，路径基本都直接写在命令里，所以这一层够用。防恶意绕过不在这一版的范围内。

工作区里的危险操作（`git reset --hard`、`rm -rf src`）不归这一层管，仍由现有黑名单强制确认。

## 2. 什么时候检查

同时满足：

1. 会话锁定了工作区（有 `lockedRoot`）。未锁定时不检查，与文件工具的写边界一致。
2. 设置里的「跳过权限确认」（`skipPermissionChecks`）是关的。默认关。开着时不检查越界写入，命令直接执行。

覆盖的工具就是现在走 Shell 强制确认的那些：`run_command`（前台、后台是同一次调用），以及 Shell 协作模式下的 `shell_exec`、`interactive_shell`（start）。

判断顺序：硬拦截 → 黑名单确认 → 工作区外写入确认。前面的命中了就不再往下判断，一条命令最多弹一次确认。硬拦截不看跳过开关；后两步都看。

## 3. 怎么判断

### 3.1 拆命令

复用 `src/tools/shell-command-parser.ts`：它已经按 `&&`、`||`、`;`、`|`、换行拆分，并展开 `cmd /c`、`powershell -Command`、`bash -c` 里的内层命令。

要补一处：cmd 的单个 `&` 也是分隔符，现在不拆。`2>&1`、`>&` 这类重定向里的 `&` 不拆。

### 3.2 跟踪当前目录

起点是工具的工作目录。按顺序处理每段命令：

- `cd`、`cd /d`、`pushd`、`Set-Location`、`sl` 更新当前目录，相对路径按当前目录解析。
- 内层命令（`cmd /c ...` 等）从外层当时的目录开始算。
- `cd` 的目标解析不了（含变量、命令替换）时，之后相对路径的写入都按「无法确定位置」处理。

### 3.3 哪些算写

| 类别 | 命令 | 取哪些参数 |
|------|------|------------|
| 删除 | `rm`、`rmdir`、`rd`、`del`、`erase`、`unlink`、`Remove-Item`（及别名 `ri`） | 所有非选项参数 |
| 移动、改名 | `mv`、`move`、`ren`、`rename`、`Move-Item`（`mi`）、`Rename-Item`（`rni`） | 所有非选项参数 |
| 复制 | `cp`、`copy`、`xcopy`、`robocopy`、`Copy-Item`（`cpi`） | 只取目标：`-Destination` 的值，没有就取最后一个非选项参数 |
| 新建、写入 | `mkdir`、`md`、`touch`、`New-Item`（`ni`）、`Set-Content`（`sc`）、`Add-Content`（`ac`）、`Out-File`、`tee`、`Tee-Object` | 所有非选项参数 |
| 重定向 | 引号外的 `>`、`>>`、`1>`、`2>`、`&>` | 后面紧跟的目标 |
| 全局安装 | `npm` / `pnpm` 带 `-g` 或 `--global` 的 `install` / `i` / `add` / `uninstall` / `remove`；`yarn global add` / `remove` | 不看参数，记为「全局包目录」 |

命令名不区分大小写，去掉路径和 `.exe` 后再比较。

选项的判断：

- `-` 开头的是选项。PowerShell 的 `-Recurse C:\x` 里，`C:\x` 仍算非选项参数，所以不需要知道哪些是开关。
- cmd 自带的命令（`del`、`rd`、`copy`、`xcopy`、`robocopy`、`move`、`md`、`ren`）里，`/s`、`/q`、`/MIR` 这种斜杠参数是选项。其他命令里 `/` 开头的是路径。

「所有非选项参数」会把 `-ItemType File` 里的 `File` 也当成路径。它按相对路径解析后落在工作区内，不影响结果。

### 3.4 解析路径

1. 引号由 tokenizer 去掉。
2. 展开 `~`、`%VAR%`、`$env:VAR`、`$HOME`、`$VAR`、`${VAR}`，取值来自宿主进程环境（子进程环境就是它加上几项）。
3. 带 `*`、`?` 的只看通配符之前的目录部分，例如 `..\*` 按 `..` 判断。
4. 相对路径按当前目录解析。
5. 取最近已存在祖先的真实路径，防止工作区里的 junction 指向区外。复用 `realpathOfNearestExisting`。

解析不了的参数（含 `$(...)`、反引号、未定义的变量）按越界处理，标为「无法确定位置」。

### 3.5 放行

以下目标不算越界：

- 工作区内（按真实路径判断）
- 系统临时目录（`os.tmpdir()`）
- 长期记忆目录。它有自己的门控 `assertAgentMemoryShellCommandAllowed`，这里不重复确认
- 空设备：`nul`、`NUL`、`/dev/null`、`$null`

`referenceReads` 里的目录是只读引用，写进去同样要确认。

## 4. 确认

复用黑名单的强制确认流程（`ShellMandatoryConfirmRequest`），只是风险内容不同：

| 字段 | 值 |
|------|-----|
| `category` | `工作区外写入` |
| `matchedPattern` | 第一个越界目标 |
| `impact` | `会写到工作区外：<最多 3 个路径>`；有解析不了的就写 `无法确定写入位置：<原始参数>` |

和黑名单确认走同一条通道，是否弹框只看设置里的「跳过权限确认」：

| 开关 | 黑名单强制确认 | 工作区外写入确认 | 普通工具确认 |
|------|----------------|------------------|--------------|
| 关（默认） | 弹 | 弹 | 按权限规则 |
| 开 | 不弹，直接执行 | 不弹，直接执行 | 不弹，直接执行 |

现在黑名单强制确认不受这个开关影响，设置页也写着「不能绕过强制确认」。这一版改掉，三类确认都连到同一个开关。开关文案是「开启后不再弹出确认」，改完之后这句话成立。

开关关掉时：

- 确认框显示命令、命中规则、风险类别、影响。
- 用户拒绝后命令不执行；同一次运行里同一条命令不再重复询问。
- 没有确认通道（无界面运行）时按拒绝处理。

开关开着时不进入确认回调。没有确认通道也不拦截。

始终不受这个开关影响：

- 灾难命令硬拦截、HostGuard
- 权限规则里显式的 deny
- 长期记忆写入门控（`assertAgentMemoryShellCommandAllowed`）

Shell 协作模式里的文件工具确认现在也不受这个开关影响（`runConfirmChecks = isShellFileTool || !skipPermissionChecks`）。一并改成受它控制，否则开了跳过确认，`/shell` 里改文件仍会弹框。

拒绝时，给模型的结果末尾加一句：不要换写法绕过；确实要写到工作区外，请让用户先切换工作区。

## 6. 配置

不新增配置项。用现有的 `skipPermissionChecks`，设置页名称是「跳过权限确认」，默认 `false`。

```json
{
  "skipPermissionChecks": false
}
```

设为 `true` 后，普通工具确认、黑名单强制确认、工作区外写入确认、Shell 协作里的文件工具确认都不弹。硬拦截、HostGuard、显式 deny、记忆写入门控照旧。新会话生效，和现在这个开关的生效时机一样。

## 7. 测试

`findOutsideWorkspaceWrites` 是纯函数，用 vitest 在临时目录里建工作区和 junction 测。

**要确认：**

- `rm -rf ../other`
- `cd .. && rmdir /s /q other`
- `cd %APPDATA% & del x.txt`
- `del /q C:\Users\me\Desktop\a.txt`
- `echo x > %USERPROFILE%\a.txt`
- `copy src.txt D:\backup\`
- `powershell -Command "Remove-Item -Recurse -Force ~\Downloads\x"`
- `powershell -Command "Copy-Item a.txt -Destination ..\x"`
- `npm i -g typescript`
- 工作区里的 junction 指向区外：`rm -rf link\x`
- `rm -rf $(cat list.txt)`（无法确定位置）

**不确认：**

- `rm -rf dist`、`del /q build\*.log`、`mkdir src\new`
- `copy C:\templates\a.txt .`（源在区外，目标在区内）
- `npm test > out.log 2>&1`、`build > nul`
- `echo hi > %TEMP%\x.txt`
- `echo "a > C:\b"`（`>` 在引号里）
- `npm install`（不带 `-g`）
- 未锁定工作区时的任何命令

**集成：**

- 同时命中黑名单和越界写入，只弹一次确认，显示黑名单的规则。
- `skipPermissionChecks: true` 时，上面「要确认」的命令直接执行，不调用确认回调；`rm -rf /` 这类硬拦截仍然拒绝。
- `skipPermissionChecks: false`（或缺省）时行为与上表一致。

## 8. 先不做

- 脚本和程序内部的写入：`node x.js`、`python -c`、编译器 `--outDir ../x` 这类。
- 程序自带的区外写入：npm 缓存、`git push` 写 `known_hosts`、凭据管理器。
- `git` 工具。它的子命令有白名单，路径都在仓库内；`git config --global` 暂不检查。
- 未锁定工作区的会话。
- 系统级隔离（写受限令牌、目录 ACL）。以后需要防恶意绕过时另起设计。
