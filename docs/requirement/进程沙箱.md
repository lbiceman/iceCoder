# 进程沙箱 — 设计

> **状态**：设计，未实现
> **版本**：v0.2
> **日期**：2026-10-29
> **范围**：Agent 发起的 shell 进程（含 `git` 工具）的文件系统与进程边界。命令文本策略（`shell-sandbox` / HostGuard）、文件工具写边界、权限确认保持原样。

[`shell-双轨执行-finish.md`](./shell-双轨执行-finish.md) 把 Bubblewrap / Seatbelt / Landlock / WSL2 列为非目标。那份文档约束的是前后台分流，不覆盖本设计。本设计补的是进程真正跑起来之后的权限，不改分流、超时和后台任务协议。

**v0.2 变更**：对照源码修正现状（`buildShellChildEnv` 的位置与行为、`git` 工具的拼接执行、后台日志由宿主写入、`lockedRoot` 的来源）；明确第一期只限写、不限读；补上 Windows 后端的实现载体、可写根准入、受保护路径、临时目录、失败与升级策略、spike 验证项和验收清单。

---

## 1. 目标

Agent 执行命令时，进程不再继承当前用户的全部磁盘写权限。

1. **写有边界。** 默认可写范围是锁定的工作区、该会话的沙箱临时目录、探测到的包管理缓存，以及用户在配置里登记的额外可写根。
2. **区外依赖仍可用。** 工具链、包缓存、另一份源码照常可读、可执行；只有登记过的根可写。
3. **入口只有一处。** 前台 `run_command`、后台任务、`git` 工具都经过同一个 `spawnInSandbox`。以后换内核只改这一处。
4. **未锁定工作区时不套这层限制。** 与现有文件写边界一致：没有 `lockedRoot` 就不做文件系统沙箱。
5. **被拦时有出路。** 写入被拒时，结果里说明是沙箱拦的；确需写到边界外时，经用户确认后在沙箱外执行，而不是让模型换写法硬绕。

### 1.1 第一期挡什么

| 场景 | 第一期 | 说明 |
|------|--------|------|
| 写到可写根以外（含 junction / symlink 绕行） | 挡 | 本设计主体 |
| 改 iceCoder 自身配置、MCP 配置、长期记忆目录 | 挡 | §3.4 受保护路径 |
| 在工作区里埋 `.git/hooks`、改 `.git/config`，等沙箱外的 git 去执行 | 挡 | §3.4 |
| 读区外文件（`.ssh`、`~/.iceCoder/config.json` 里的 API key） | **不挡** | Windows 写受限令牌只管写；读限制另做（§7 阶段 3） |
| 联网外传 | **不挡** | §3.8 |
| 杀宿主进程 | HostGuard 挡；沙箱预期能补一层 | 需 spike 确认（§5.6） |

第一期的定位是防误删、误改，以及模型绕开命令正则写出边界，不是防数据外泄。对外文档按这个口径写。

## 2. 现状

名字里的「沙箱」目前是命令文本策略，进程仍以当前用户身份裸启动。

### 2.1 命令文本策略

`analyzeShellSandbox`（`src/tools/shell-sandbox.ts`）做三件事：

| 层 | 行为 | 热路径 |
|----|------|--------|
| 硬拦截 | `rm -rf /`、`format` 盘符等灾难命令，不能被 `shellBlacklist: []` 关掉 | 执行前拒绝 |
| HostGuard | 误杀宿主 `node` / 当前 PID；`node script.js` 执行前读文件扫描 | 执行前拒绝 |
| 可配置黑名单 | `data/config` 里的 `shellBlacklist` 正则 | **不在执行期拒绝** |

热路径把黑名单关掉了：`src/tools/builtin/shell-tool.ts`、`src/tools/background-task-manager.ts`、`src/harness/harness-tool-preflight.ts` 调用时都是 `includeBlacklist: false`。黑名单实际走协作模式的强制确认（`src/tools/shell-collab-command-risk.ts`）。

HostGuard 分三层：

| 层 | 位置 | 扫什么 |
|----|------|--------|
| L1 | `src/tools/shell-host-guard.ts` | `run_command` 字面量 |
| L2 | 同上 | `node script.cjs` 执行前读脚本内容 |
| L3 | `src/harness/harness-tool-preflight.ts` | `write_file` / `edit_file` / `patch_file` 等写入内容 |

这些规则留下。它们挡已知坏命令；进程沙箱挡正则没覆盖到的路径。

### 2.2 文件工具的写边界与工作区锁

工作区锁定之后，写类文件工具的目标必须在工作区内（`checkWorkspaceWriteBoundary`）。`referenceReads` 只允许读，写入同样被拦。长期记忆目录除外。未锁定时不限制。

`run_command` 没有对应的磁盘边界。`cwd` 设在工作区，命令可以 `cd` 出去、用绝对路径读写、带上宿主环境变量。

`lockedRoot` 不是用户在界面上显式选的。`detectWorkspaceFromUserMessage`（`src/harness/workspace-lock.ts`）按规则从用户消息里提取路径并打分：带「实现 / 开发 / 工作目录:」等关键词，或单独成行的目录路径，会被锁成工作区。用户随口提到的 `C:\Users\<me>` 也可能被锁。文件工具只拿它判断路径归属，误判代价小；进程沙箱要拿它去改目录 ACL，所以授权前必须先过准入（§3.5）。

未锁定时，`resolveEffectiveWorkspaceRoot`（`src/harness/session-workspace-store.ts`）回退到默认工作目录，顺序是桌面端保存的 `workspace.json`、数据目录、用户主目录（`resolveSharedDefaultWorkDir`，`src/runtime/shell-identity.ts`）。后两者绝不能当可写根。

区外只读路径已经有登记入口：`workspace-lock.ts` 从用户消息识别引用；`addSessionReferenceReads` 把 imagesCache 等会话外路径记入 `referenceReads`。

### 2.3 进程出口

| 入口 | 文件 | 执行方式 | 第一期 |
|------|------|----------|--------|
| 前台 `run_command` | `src/tools/builtin/shell-tool.ts` | `spawn(cmd.exe, ['/c', command])` | 接入 |
| 后台任务（含前台超时移交 `adopt`） | `src/tools/background-task-manager.ts` | 同上 | 接入。移交的是已经在沙箱里的进程，不重新 spawn |
| `git` 工具 | `src/tools/builtin/git-tool.ts` | `execFile(git.exe, argv)`，不经过 shell。子命令有白名单 | 接入 `spawnInSandbox`，见下 |
| Shell 协作模式 PTY（`interactive_shell` / `shell_exec` / `shell_wait` / `shell_send_keys`） | `src/tools/interactive-shell-manager.ts` | `node-pty` | 第二期。只在 Shell 协作模式注入（`src/tools/shell-collab-tools.ts`），该模式下命令本来就走强制确认 |
| ripgrep | `src/tools/builtin/ripgrep-runner.ts` | `spawn(rg, args)` | 不接。只读搜索，参数由运行时拼，模型传不了 `--pre` 这类参数 |
| `env_info`、文件浏览列盘符 | `env-info-tool.ts`、`filesystem-browser-tool.ts` | 固定命令（`node --version`、`wmic logicaldisk`） | 不接。命令文本不受模型控制 |
| MCP | `src/mcp/mcp-client.ts` | | 保持在沙箱外。用户启用的 MCP 等于额外授权一个本机进程 |
| cloudflared | `src/dev/tunnel/cloudflared-tunnel.ts` | | 产品进程，不是 Agent 命令 |

`git` 工具的命令注入已经修掉：`args` 按引号拆成 argv，`execFile` 直接启动 `git.exe`，不再经过 `cmd.exe`。`{"subcommand":"status","args":"& <任意命令>"}` 不会再执行第二条命令。子命令也限制在白名单里。

还没修的是配置即执行。`git config core.fsmonitor <命令>` 或 `git config alias.status "!<命令>"` 之后，再跑 `git status` 时，命令仍由 git 自己拉起，不经过 shell 拼接那一层。沙箱落地时 `runGit` 改走 `spawnInSandbox`，`.git/config` 设为受保护路径（§3.4），沙箱内写不进去。环境变量仍是 `process.env` 加上 `GIT_TERMINAL_PROMPT`；`buildShellChildEnv` 留到沙箱一起做。

桌面端 `sandbox: false`（`desktop/src/main.ts`、`desktop/src/ping/overlay.ts`）是 Electron 渲染进程开关，和 Agent 沙箱无关。

`npm run eval:agent` 的「沙箱」是 `os.tmpdir()` 下的临时工程目录（`scripts/agent-eval-runner.ts`），用来隔离回归用例，不隔离进程权限。

### 2.4 子进程环境变量

`buildShellChildEnv` 在 `src/tools/shell-host-guard.ts`。它把 `process.env` 整份展开，只补 `PATH`、`ICE_AGENT_ROOT_PID`、`ICE_AGENT_SESSION`，**没有剥离任何变量**。`git` 工具直接展开 `process.env`。PTY 也走 `buildShellChildEnv`。

另外它强制 `NODE_ENV=production`。npm 在 `NODE_ENV=production` 时默认 `omit=dev`，Agent 跑 `npm install` 会跳过 devDependencies。这不属于沙箱范围，单独修。

### 2.5 后台日志由宿主写

`BackgroundTaskManager.openLogStream` 在宿主进程里用 `createWriteStream` 写 `data/sessions/<id>/bg/<taskId>.log`，子进程输出经管道转写。命令进程不需要这个目录的写权限。v0.1 把它列进可写根是多余的，还会让命令进程能改宿主读回的日志。

### 2.6 命令碰过哪些文件

`src/harness/workspace-command-touch.ts` 用执行前后的工作区清单对比，记录命令造成的工作区变动。它只观察工作区内部，看不到写出工作区的动作，不能当作沙箱。

## 3. 边界模型

沙箱边界是一组带权限的根，不是「机器上只剩工作区这一个目录」。第一期只管写：所有路径照常可读、可执行，写入只能落在登记过的根里。

| 现有字段 | 沙箱里的含义 |
|----------|----------------|
| `lockedRoot` | 默认可写根，需过 §3.5 准入 |
| `referenceReads` | 区外只读根。第一期全盘可读，这个字段在进程侧暂时不产生差别；文件工具照旧用它；阶段 3 做读限制时，它成为可读白名单的一部分 |

会话没有 `lockedRoot` 时不启用文件系统沙箱。

v0.1 的「可执行根」去掉：Windows 写受限令牌不区分读和执行，第一期没有这一维。Linux / macOS 后端以后需要时再加。

### 3.1 三类区外路径

**工具链：可读、可执行，不可写。** Node、Git、`cmd`、系统目录都在工作区外。没有登记成可写根就不可写，不需要额外配置。`Program Files` 里的 Git 能调用，不能被改。

**包和缓存：少数目录可写。** `node_modules` 一般在工作区内，跟着工作区走。真正在外面的是 npm cache、pnpm store、yarn cache，以及 pip、Cargo、Go 的缓存。第一期只放行 npm / pnpm / yarn 的缓存目录，其余由用户在 `extraWritableRoots`（§6.1）里登记。缓存路径由宿主读本机配置得到（`npm config get cache`、`pnpm store path`）。探测在启动时做一次并缓存结果，不在每次 spawn 时跑；不接受模型在命令里临时指定的路径。

可写缓存是跨项目共享的：沙箱进程可以往 pnpm store 里写一个被篡改的包，影响其他项目。这是为了让 `install` 能用而接受的代价，写进使用文档。

**另一份源码：只读。** 旁边的库、另一个仓库、规范文档记入 `referenceReads`。需要改那份代码时，把它加成可写根，和切换工作区是同一件事，不把整个父目录悄悄放开。

### 3.2 默认权限

| 权限 | 第一期包含 |
|------|------------|
| 可写 | 锁定的工作区（扣除受保护路径）、会话沙箱临时目录、探测到的 npm / pnpm / yarn 缓存、配置里的 `extraWritableRoots` |
| 只读 | 其余所有路径 |
| 不可读 | 第一期没有。`.ssh`、`.aws`、`.gnupg` 的读限制放到阶段 3 |

工作区内的 `.env` 照常可读写。`git fetch` / `git push` 需要写 `~/.ssh/known_hosts` 或凭据存储时，走沙箱外执行（§6.4）。

### 3.3 Junction / symlink

进程侧不需要对每次写入做 realpath 判断。内核打开文件时先解析重解析点，再对最终目标做访问检查。工作区里一个指向区外的 junction，写穿过去时检查的是区外目标的 ACL，自然被拒。

realpath 只在装配策略时用：每个可写根先取真实路径，再做准入（§3.5）和授权，避免把一个指向 `C:\Users\<me>` 的 junction 当成工作区授权出去。规则和文件工具侧的 `realpathOfNearestExisting`（`harness-tool-preflight.ts`）一致。

### 3.4 受保护路径

有些路径即使落在可写根里也不给写，因为写进去的内容之后会被沙箱外的进程执行，或者被当成授权。

| 路径 | 原因 |
|------|------|
| `ICE_DATA_DIR`（含 `config.json`、`sessions`、长期记忆目录）、`ICE_CONFIG_PATH`、`ICE_MCP_CONFIG_PATH` 所在目录 | 改权限规则、加 MCP 服务器等于自我授权，而 MCP 在沙箱外启动。开发态的 MCP 配置在仓库内 `.iceCoder/mcp.json`，用 iceCoder 开发 iceCoder 时正好落在工作区里 |
| 工作区根的 `.git` 目录本身、`.git/hooks`、`.git/config` | 用户、IDE、沙箱外的 git 之后会执行 hooks，以及 `core.fsmonitor`、`core.sshCommand`、alias。`.git` 本身禁删、禁改名，防止被整体换掉 |

`.git/objects`、`refs`、`index`、`HEAD` 仍可写，`git add`、`commit`、`checkout` 能在沙箱里跑。`git remote add`、`git push -u` 这类要改 `.git/config` 的操作会失败，走沙箱外执行。

几个已知缺口，第一期接受：

- 只保护工作区根的 `.git`。之后在工作区里新建或克隆的仓库不在保护范围内。
- `.git` 是文件（worktree / submodule）时，真正的 gitdir 在工作区外，本来就不可写，这类仓库的 `git commit` 在沙箱里会失败，结果里提示走沙箱外执行。
- `.vscode/tasks.json`、`package.json` 的 scripts 这类会被用户或 IDE 之后执行的文件不做保护。

长期记忆目录在数据目录里，进程侧不可写。现在 `assertAgentMemoryShellCommandAllowed`（`src/memory/file-memory/memory-write-pipeline.ts`）在用户明确要求记住时允许用 shell 写记忆；接入沙箱后这条路会失败，记忆写入统一走文件工具（已有例外）。

### 3.5 可写根准入

`lockedRoot` 来自规则检测（§2.2），授权前先过准入。命中下列任一条，沙箱拒绝启动命令并说明原因，请用户换一个更具体的工作区，或关掉沙箱：

- 盘符根（`C:\`、`D:\`）。
- 用户主目录本身或它的祖先。主目录下的具体项目目录可以。
- `%SystemRoot%`、`Program Files`、`Program Files (x86)`、`ProgramData` 及其子目录。
- iceCoder 数据目录，或它的祖先。
- 不支持 ACL 的卷（FAT32 / exFAT）和网络共享。

判断基于真实路径。`extraWritableRoots` 走同一套准入。

### 3.6 临时目录

命令进程的 `%TEMP%` 原本在 `C:\Users\<me>\AppData\Local\Temp`，不在可写根里。几乎所有工具链都写临时文件，不处理的话第一期大部分命令会失败。

每个会话一个临时目录 `%TEMP%\iceCoder-sandbox\<sessionId>`，只授权这一级，并把子进程的 `TEMP`、`TMP`、`TMPDIR` 指过去。会话结束时清理。

### 3.7 环境变量

子进程继续走 `buildShellChildEnv`，第一期改两点：

1. 剥离值等于 iceCoder 已配置的模型 API key 的变量。按值匹配，不按名字猜，避免把 `GITHUB_TOKEN`、`NPM_TOKEN` 这类命令确实要用的变量剥掉。
2. 注入 §3.6 的临时目录。

第一期不限读，命令进程照样能读 `~/.iceCoder/config.json`。剥环境变量防的是 key 被顺手打进日志和输出，不是防外泄。

`NODE_ENV=production` 的问题见 §2.4，单独修。

### 3.8 网络

第一期放行。编码助手一禁网，`npm install`、`git fetch` 立刻不能用。

文件系统稳定之后再做显式档位，而不是默认全禁：

| 档位 | 行为 |
|------|------|
| 放行 | 第一期默认 |
| 限定 | 只允许包源和 git 远程 |
| 全禁 | 只适合纯本地改代码 |

### 3.9 进程

HostGuard 继续禁止杀掉宿主 PID，以及按镜像名广杀 `node`。写受限令牌对写类访问额外检查受限 SID；如果结束进程也落在这道检查里，命令进程就打不开宿主进程的终止句柄，能兜住脚本间接调用、编码绕过这类 HostGuard 漏掉的写法。spike 确认之前（§5.6），不把这一点当成保证。

反方向不能受影响：宿主要能结束沙箱进程树（`src/tools/shell-process-kill.ts` 的 `taskkill /T /F`），沙箱里的进程要能结束自己起的子进程（例如 `npm run dev` 下的 node）。

## 4. 统一入口

新建 `src/tools/sandbox/`，放策略装配和 `spawnInSandbox`。

```ts
interface SandboxPolicy {
  workspaceRoot: string;
  /** 已过准入的真实路径 */
  writableRoots: string[];
  protectedPaths: string[];
  tempDir: string;
}

function spawnInSandbox(
  file: string,
  args: string[],
  options: {
    cwd: string;
    env: NodeJS.ProcessEnv;
    sessionId: string;
    policy: SandboxPolicy | null;
  },
): ChildProcess;
```

- 策略只由运行时装配：工作区锁、缓存探测、用户配置。模型不能通过工具参数追加根。
- `policy` 为 `null`（未锁定，或 `mode: off`）时等同现在的 `spawn`。
- 返回值仍是 `ChildProcess`。调用方现有的输出采集、超时、`adopt` 移交、`killShellProcessTree` 都不用改。
- 预检（`checkToolPreflight`）仍只挡已知灾难命令和 HostGuard。能不能写出可写根，由这次 spawn 决定。
- 文件工具写边界和进程边界读同一份 `lockedRoot`。

## 5. Windows 后端

开发机是 Windows（当前仓库在 `win32` 上跑），第一份真正生效的后端是写受限令牌，范围是前台 `run_command`、后台任务和 `git` 工具。

不把第一期押在 WSL2 上。本机仓库、`node-pty`、桌面端和工作区锁都是 Windows 路径，绕进 WSL 会拆掉现有路径锁定。

Job Object 只能管进程树，不管磁盘，不能单独当文件系统沙箱。它在这里用来保证进程树一起结束。

### 5.1 载体：独立辅助程序

Node 的 `child_process.spawn` 不能指定令牌，需要原生代码。两种载体：

| 方案 | 代价 |
|------|------|
| N-API 原生模块 | 要分别为 Node 和 Electron 的 ABI 编译，随版本升级重编；崩溃会带走宿主进程 |
| 独立辅助程序 `ice-sandbox-run.exe` | 每次 spawn 多一个进程，开销需实测（§5.6） |

选辅助程序。用 Rust 或 C++ 写，静态链接，不依赖运行时。源码放 `native/sandbox-runner/`，CI 产出 x64 / arm64 二进制，npm 包和桌面安装包都带上。

### 5.2 辅助程序做什么

1. 接收策略：本次可写根对应的 SID 列表。通过命令行参数或继承的句柄传入，不从模型可写的位置读文件。
2. 从自身令牌派生写受限令牌：`CreateRestrictedToken`，标志 `DISABLE_MAX_PRIVILEGE | LUA_TOKEN | WRITE_RESTRICTED`，受限 SID 为本次可写根的 SID。令牌的默认 DACL 要补上这些 SID，否则子进程写不了自己创建的命名管道、事件这类对象。
3. 建 Job Object，设置 `KILL_ON_JOB_CLOSE`，不允许 breakaway。辅助程序被结束时整棵树一起结束。
4. `CreateProcessAsUserW` 启动真正的命令，继承标准输入输出句柄。令牌派生自调用方自身令牌时不需要 `SeAssignPrimaryTokenPrivilege`，普通用户即可。
5. 命令行原样作为 `lpCommandLine`，不做二次转义。子进程拿到的命令行必须与现在逐字节一致，否则 `cmd.exe /c` 对引号和中文路径的处理会变。
6. 等子进程退出，原样返回退出码。

写受限令牌的语义：读和执行只按原令牌检查，行为不变；写入要求原令牌和受限 SID 两次检查都通过。所以只有显式授权给沙箱 SID 的位置能写，其余位置即使当前用户有权限也写不了。

受限 SID 里不放 `Everyone`、`Users`、`Authenticated Users`。放了的话，`C:\` 根、`ProgramData`、`C:\Users\Public` 这类对这些组开放写的位置也会变成可写。如果 spike 发现必须放（例如控制台或某些系统对象依赖），再加一步：扫描这些组可写的目录，给沙箱 SID 加拒绝写的 ACE。

### 5.3 SID 与 ACL

每个可写根一个随机 SID：工作区一个，缓存共用一个，会话临时目录一个。登记在 `{ICE_DATA_DIR}/sandbox/grants.json`。不用全局一个 SID，否则任何会话都能写所有曾经授权过的工作区。

- **授权。** 给根目录加一条对该 SID 的可继承「修改」ACE。首次授权要把继承传播到整棵树，带 `node_modules` 的大仓库可能要几十秒。只做一次，之后按 `grants.json` 判断已授权。耗时要在 spike 里实测。根目录的 ACL 改不了（没有 `WRITE_DAC`，例如以管理员身份克隆的仓库）时按授权失败处理（§6.2）。
- **受保护路径。** 在对应位置加该 SID 的拒绝写、拒绝删除 ACE。
- **残留。** 切换工作区后，旧 ACE 留在磁盘上。每个根一个 SID，没有令牌带着旧 SID 就不生效。提供 `iceCoder sandbox status` / `iceCoder sandbox reset` 列出和撤销授权。
- **传播不能跟随重解析点。** 沙箱进程可以在工作区里建一个指向区外的 junction；如果重新授权时传播顺着它走下去，就会把区外目录授权出去。系统 API 的传播行为要 spike 确认，不满足就自己遍历并跳过重解析点。硬链接同理：pnpm 的 `node_modules/.pnpm` 是指向 store 的硬链接，传播会不会改到 store 里文件的 ACL，也要确认。

### 5.4 已知兼容问题

| 场景 | 现象 | 处理 |
|------|------|------|
| 创建 symlink | `DISABLE_MAX_PRIVILEGE` 去掉了 `SeCreateSymbolicLinkPrivilege`；开了开发者模式的机器不受影响；junction 不需要特权 | 结果里提示。pnpm 在 Windows 上用 junction，不受影响 |
| 写 HKCU 注册表 | 注册表同样受写限制 | 遇到再登记，走沙箱外执行 |
| 全局安装 `npm i -g`、`pip install --user` | 目标在用户目录 | 沙箱外执行 |
| `git fetch` / `push` 首次连 SSH 主机、保存凭据 | 要写 `~/.ssh/known_hosts`、凭据管理器 | 沙箱外执行；spike 确认 HTTPS 已缓存凭据时能否直接成功 |
| 工具自带缓存：`node-gyp`、Playwright 浏览器、Electron 下载缓存、PowerShell 模块分析缓存 | 写 `%LOCALAPPDATA%` 下各自目录 | `extraWritableRoots` 登记，或沙箱外执行 |
| 工作区在网络共享、FAT32 / exFAT 卷 | 无法授权 | 准入拒绝（§3.5） |

### 5.5 Linux / macOS

后补，策略对象不变：

| 平台 | 做法 |
|------|------|
| Linux | Bubblewrap：根目录只读挂载，可写根读写挂载，受保护路径再以只读覆盖 |
| macOS | Seatbelt profile，同一份策略 |

这两个平台不改持久 ACL，§5.3 的授权耗时和残留问题不存在。

### 5.6 Spike 验证项

开工前先用辅助程序原型逐条验证，结论写回本文档。任何一条不成立都要先改设计：

1. 受限 SID 只放沙箱 SID 时，`cmd.exe`、`powershell.exe`、`node.exe`、`git.exe`、Git Bash 能否正常启动和退出；需要补的默认 DACL 或额外 SID 是什么。
2. 临时目录重定向后，`npm install`、`pnpm install`、`npx tsc`、`npx vitest run` 能否跑通。
3. 写工作区外、经 junction 写区外，是否都返回拒绝访问。
4. 沙箱进程能否结束宿主 node 进程；宿主能否用 `taskkill /T /F` 结束沙箱进程树；沙箱进程能否结束自己起的子进程。
5. 首次 ACL 传播在本仓库（含 `node_modules`）上的耗时；传播是否跟随 junction；是否经硬链接改到 pnpm store 里的文件。
6. 每次 spawn 多出的耗时。
7. HTTPS 已缓存凭据时，`git fetch` 能否在沙箱内成功。

## 6. 配置、失败与升级

### 6.1 配置

`data/config` 新增：

```json
{
  "sandbox": {
    "mode": "off",
    "extraWritableRoots": []
  }
}
```

- `mode`：`off` 或 `enforce`。spike 和 §8 兼容验收通过前默认 `off`，之后改为 `enforce`。
- `extraWritableRoots`：用户登记的额外可写根，过 §3.5 准入。模型不能通过工具参数追加。

### 6.2 后端不可用

`enforce` 下，辅助程序缺失、令牌创建失败、授权失败、可写根未过准入时，拒绝执行并说明原因，不静默退回裸启动。错误信息给出两条出路：换工作区，或在设置里把 `mode` 改成 `off`。

会话界面显示本会话的沙箱状态：已启用、未启用（未锁定工作区 / Shell 协作模式）、已关闭（配置）、不可用（附原因）。

### 6.3 被拒时的提示

`enforce` 下命令非零退出，且输出里出现 `Access is denied`、`拒绝访问`、`EPERM`、`EACCES`、`Permission denied` 时，工具结果末尾追加一段说明：写入可能被沙箱拦截、当前可写根有哪些、怎样申请沙箱外执行。没有这段，模型会把「拒绝访问」当普通错误，换各种写法重试。

这是启发式判断，只追加提示，不改退出码。

### 6.4 沙箱外执行

`run_command` 和 `git` 工具增加两个参数：`unsandboxed: true` 和必填的 `reason`。带 `unsandboxed` 的调用一律走权限确认，界面上显示命令和原因。用户可以在权限规则里对具体命令前缀放行（例如 `git push`），默认不放行。

沙箱外执行逐次确认，不是会话级开关。模型没有其他参数能扩大可写根。

## 8. 验收

**隔离**

- 在工作区内写文件，成功。
- 写到工作区外（例如用户目录下的临时文件），失败。
- 通过 junction / symlink 把写入指到工作区外，失败。
- 写 `.git/hooks/pre-commit`、执行 `git config core.fsmonitor <命令>`，失败。
- 写 iceCoder 数据目录、MCP 配置文件，失败。
- `git` 工具的 `args` 带 `& echo pwned`，第二条命令不执行。
- 工作区被锁到用户主目录时，命令被拒并给出原因。
- （视 spike 结论）沙箱进程结束宿主 PID，失败。

**兼容**

- 本仓库里 `npm install`、`pnpm install`、`npx tsc --noEmit`、`npm test` 通过。
- `git status`、`git add`、`git commit` 在沙箱内成功。
- `python -c`、`powershell -NoProfile -Command` 正常执行。
- 命令写 `%TEMP%` 落到会话临时目录，会话结束后被清理。
- 后台起 dev server 后 `check`、`kill` 正常；前台超时移交后台正常；中止时整棵进程树结束。
- 退出码、中文输出、带引号和中文的路径，与现在一致。

**性能与失败**

- 记录单次 spawn 的额外耗时；目标值在 spike 之后定。
- 辅助程序缺失时，`enforce` 拒绝执行，`off` 正常执行。

## 9. 非目标

- 不替换 `analyzeShellSandbox`、HostGuard、协作模式强制确认、权限规则（allow / confirm / deny）。
- 不把未锁定会话改成默认限制。
- 不让模型在对话里声明可写路径。额外可写根只来自用户切换工作区、探测到的包管理缓存，或用户配置的 `extraWritableRoots`。
- 不做命令白名单文件。
- 第一期不限读、不做网络隔离、不做 PTY、不做 MCP 沙箱、不做 WSL2。
- 不改 Eval 临时目录的含义。进程沙箱落地后，Eval 只是多跑在一个已锁定的临时工作区里。
