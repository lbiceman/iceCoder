# Shell 协作模式（`/shell`）

> 在聊天里与 AI 协作完成 **交互式终端任务**（SSH 登录、远程考试、多段密码提示、`yes/no` 确认等），**无需盯着黑窗口**。  
> 设计背景见 [`requirement/shell-交互协管-slash-shell.md`](./requirement/shell-交互协管-slash-shell.md)。

---

## 是什么

**Shell 协作模式**让 iceCoder 在后台托管一条 **持久 PTY 终端会话**。AI 读取终端输出、用人话汇报；你在聊天里做决策或提供密码；AI 代写 stdin，循环直到任务结束。

与 **`run_command`（短命令）** 不同：Shell 模式面向 **长连接、多轮交互** 的 shell（如 SSH 进去后的远程 bash），同一会话里 **PTY 不断开**。

| 对比 | 普通 Agent 会话 | Shell 协作会话 |
|------|-----------------|----------------|
| 进入方式 | 新建会话后直接聊 | 发送 **`/shell`** 一次 |
| 工具集 | 文件/Git/MCP/短命令等 | **仅** Shell 专用工具（见下文） |
| 终端 UI | 无 | **无**（不内嵌 xterm；AI 摘要代替滚屏） |
| 典型场景 | 改代码、读仓库 | SSH、考试系统、交互式运维 |

---

## 如何进入

在 **Web / 桌面 / 移动端 H5** 的聊天输入框发送：

```text
/shell
```

或同一条消息里带上首条说明：

```text
/shell
ssh student@exam.example.com
```

```text
/shell 帮我连接 192.168.1.10，用户 root
```

也可在输入 `/` 后从斜杠命令面板选择 **shell**。

### 进入之后

- 该 **会话永久固定** 为 Shell 协作模式，侧栏会话项与输入区底部会显示 **Shell** 标识。
- **后续消息不必再带 `/shell`**，直接像普通聊天一样发即可。
- 如需普通 Agent（改文件、MCP、PDF 等），请 **新建会话**。

### 如何退出

- Shell 协作是 **会话级单向能力**：进入后 **不能** 用 `/shell exit` 切回普通模式（`/shell exit` 仅作无效提示，不改变模式）。
- **删除该会话** 会清理 Shell 状态并终止 PTY。
- 想同时做 Shell 任务和普通编码，请 **开两个会话**。

## 推荐使用方式

### 1. 连接远程主机（SSH）

```text
你: /shell
AI: 已进入 Shell 协作模式。请说明如何连接。

你: ssh student@192.168.70.54
AI: 正在连接……终端提示：请输入密码。请把 SSH 密码发给我（会进入聊天历史，建议优先使用 SSH Key）。

你: （发送密码）
AI: 已登录。当前在远程 shell，需要我做什么？

你: 看一下磁盘使用情况
AI: （在同一轮或后续轮执行 df 等命令并汇报摘要）
```

### 2. 登录后授权 AI 自主解题

远程终端已出现题面或任务说明时，可用简短授权语：

- 「帮我执行」
- 「做一下」
- 「你来处理」

AI 会在 **同一 Harness 回合内** 先读终端题面，再连续执行 `df`、`du`、`find` 等命令并汇报，**普通命令无需逐条确认**。

### 3. 遇到交互提示时

当终端出现 **密码、账号、yes/no** 等提示时，AI 会：

1. 说明终端在问什么；
2. **结束当前 AI 回合**，等你下一条消息；
3. 你回复后，AI 再把内容写入 PTY。

你 **不需要** 复制整屏终端输出；AI 从 PTY 读取真实内容。

## 安全与确认

### 密码与敏感输入

- 密码通过 **聊天消息** 发送会 **进入会话历史**；AI 会提示风险，**优先建议使用 SSH Key / ssh-agent**。
- v1 **不提供** 独立 Secret 弹窗。

### Shell 强制确认规则

**设置 → 通用 → Shell 强制确认规则**（配置字段 `shellBlacklist`，名称为兼容保留）

- 命中规则的命令（如 `rm -rf`、`git reset --hard` 等）写入 PTY **前** 会 **弹框强制确认**。
- **未命中** 的规则：Shell 模式下 **直接执行**，不走普通工具的权限确认。
- 可在设置页编辑正则、恢复默认规则。
- 灾难性命令 hard block 与宿主保护 **不可关闭**。

## 与普通 `run_command` 的区别

| | `run_command` | Shell 协作 `/shell` |
|---|---------------|---------------------|
| 进程模型 | 短命令 / 可后台 | **持久 PTY**，跨多轮消息 |
| 交互 | 不适合 sudo 密码、vim | 适合 SSH、考试、交互式程序 |
| 会话 | 任意普通会话 | **专用 Shell 会话** |
| 工具 | 全量 Agent 工具 | 仅 Shell 白名单 |

本地一行 `npm test` 仍可用普通会话 + `run_command`；远程 SSH 里做题请用 **`/shell`**。

## 常见问题

**Q：发送 `/shell` 没反应？**  
检查是否在 **Shell 专用会话** 已激活、WebSocket 是否连接；桌面版确认安装包打包日志中有 `[rebuild-server-native] done.`。

**Q：AI 说要用文件工具 / MCP？**  
当前是 Shell 会话，只能操作 PTY。请 **新建普通会话** 做编码任务。

**Q：能否同时开 Shell 和普通 Agent？**  
可以，用 **两个会话**：一个 `/shell`，一个普通聊天。

**Q：刷新页面会丢 SSH 吗？**  
PTY 在服务端按会话保持；刷新后 **同一 session** 重连可恢复 Shell 模式标记，但 **服务重启** 不会恢复 PTY 进程（与后台任务 `[stale]` 语义一致）。

**Q：AI 没检测到密码提示？**  
提示检测为启发式 + AI 读 raw 输出兜底，**不保证 100%**；可把终端关键一句复制到聊天补充说明。
