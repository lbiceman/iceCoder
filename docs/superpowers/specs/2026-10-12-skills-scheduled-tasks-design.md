# 技能/任务与定时调度设计

## 目标

将现有“技能”入口升级为“技能/任务”。页面同时承载技能库和定时任务管理，并新增一个持久化的单计时器调度器：

1. 醒来。
2. 执行所有已到点任务。
3. 重扫任务表。
4. 找出最近的下次执行时间。
5. 用 `setTimeout` 睡眠到该时间后重复。

任务支持秒、分、时、天四种间隔单位，最大单位为天。

## 已确认的产品行为

- 每个定时任务绑定一个自动创建的独立会话，后续执行持续写入该会话。
- 技能绑定可选，可选择任意多个技能；仅填写提示词也可执行。
- 新建并启用后等待一个完整间隔再首次执行。
- 进程关闭期间错过的执行全部跳过；重启后只计算未来最近一次。
- 页面支持新建、编辑、启停、立即执行、删除及进入任务会话。
- 保留 `#/skills` 和移动端现有路由，仅修改展示名称，避免旧链接失效。

## 数据模型

定时任务持久化为 JSON，核心字段如下：

- `id`：稳定唯一标识。
- `name`：任务名称。
- `prompt`：每次执行发送的提示词。
- `skillFilenames`：零个或多个技能文件名。
- `intervalValue`：大于零的整数。
- `intervalUnit`：`second | minute | hour | day`。
- `sessionId`：任务专属会话。
- `enabled`：是否启用。
- `createdAt`、`updatedAt`：审计时间。
- `lastRunAt`：最近一次实际触发时间，可为空。
- `nextRunAt`：下一次计划时间；停用时为空。
- `lastStatus`：`idle | queued | success | error`。
- `lastError`：最近错误摘要，可为空。

文件采用临时文件写入后原子替换，避免进程中断留下半份 JSON。所有写操作串行化，防止并发 API 请求覆盖。

## 调度器

进程内只保留一个活动 `setTimeout`。

- 启动：加载任务；对已过期的启用任务按间隔向前推进到未来，跳过错过次数；持久化修正结果；安排最近任务。
- 醒来：重新从任务表获取全部到点任务，先为每个任务推进并持久化 `nextRunAt`，再触发执行，防止执行耗时或异常导致重复触发。
- 执行：将提示词和所选技能引用写入任务专属会话的现有消息队列，并复用现有 Harness 启动链路。
- 重排：任务新增、编辑、启停、删除、立即执行后，取消旧计时器并重新扫描最近时间。
- 长间隔：Node 的 `setTimeout` 有约 24.8 天上限。若目标更远，只等待安全上限；醒来后重扫，不提前执行。
- 停止：服务关闭时清除计时器，不再接受新一轮调度。

单个任务执行失败只记录状态和错误，不阻断其他任务，也不会自动停用该任务。立即执行不改变原本的周期锚点。

## API

新增 `/api/scheduled-tasks`：

- `GET /`：返回全部任务。
- `POST /`：校验输入、创建专属会话、保存任务并重排。
- `PUT /:id`：编辑名称、提示词、技能和间隔；间隔或启用状态变化时从当前时刻重新计算下一次。
- `DELETE /:id`：删除任务并重排；保留历史会话。
- `POST /:id/toggle`：启停任务。
- `POST /:id/run`：立即执行一次，不改变正常下次时间。

输入错误返回 400，不存在返回 404，磁盘或执行链路错误返回 500；响应继续遵循项目的 `{ success, ... }` 结构。

## UI

桌面侧边栏和移动端底栏将“技能”改为“技能/任务”。页面标题同名，内容分为两个页签：

- “技能”：复用现有技能卡片、详情、删除和“使用技能”能力。
- “定时任务”：顶部显示新建按钮，下面以卡片展示状态、间隔、下次执行倒计时、最近执行结果和绑定技能。

任务编辑使用与现有界面一致的深色弹层。表单包括名称、提示词、多选技能、间隔数值和单位。卡片提供启停、立即执行、编辑、进入会话和删除操作。桌面与移动端复用同一数据和行为模块，通过响应式样式调整布局。

前端在任务页可见时按秒刷新倒计时，但不轮询执行状态；用户操作后重新拉取，页面再次显示时刷新。后端时间戳是唯一事实来源。

## 边界与错误处理

- 间隔必须是正整数；单位仅允许秒、分、时、天。
- 名称和提示词去除首尾空白后不能为空。
- 保存的技能在执行前重新校验；已删除技能被忽略，并在任务状态中记录可读错误信息，提示词仍可执行。
- 任务专属会话不存在时执行失败并记录错误，不静默改投其他会话。
- 调度器按单进程设计；当前项目没有多实例协调需求。

## 测试策略

1. 持久化单元测试：CRUD、输入校验、原子保存、并发串行化。
2. 调度器单元测试：最近任务选择、同时到点、启停重排、重启跳过、长超时分段、执行失败隔离、立即执行不改周期。
3. API 集成测试：响应结构、状态码、会话创建、任务变更触发重排。
4. 执行链路测试：提示词和零个/多个技能正确入队到专属会话。
5. 前端测试：入口文案、页签、表单单位、任务操作和倒计时展示。
6. 完整验证：Vitest、TypeScript lint、Web 构建。

## 非目标

- 不支持 Cron 表达式、指定日期时间、周/月/年单位。
- 不补跑停机期间错过的次数。
- 不删除任务历史会话。
- 不引入数据库、系统计划任务或多实例分布式锁。
